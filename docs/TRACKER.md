# Tracker

The live list of everything open on Killcam and on its integration into the apps that use it. Bugs, features, and tech debt and security each have one row per item. The product-manager skill (`.agents/skills/product-manager/SKILL.md`, shared by every coding agent; Claude Code runs it as the `product-manager` agent) keeps this file current. How each feature works is in [FEATURES.md](FEATURES.md); long write-ups are in [BACKLOG.md](BACKLOG.md). Any agent or person who finds, fixes, ships or defers something updates this file, or asks the product-manager agent to.

**Statuses:**
- open: `needs-review` → `confirmed` → `in-progress`
- closed: `done`, `dismissed`, `expected`
- items can also be `planned` or `backlog`

**Priorities:**

| Priority | Rule |
|---|---|
| P0 | Wrong data shown as right, a security hole, or Killcam destroying the app's data |
| P1 | Blocks a workflow, or Killcam changes how the host app behaves |
| P2 | Friction |
| P3 | Polish |

The agent never closes an item on its own. To record a decision, change the Status cell and add the reason to the row.

| T-001 | Any app on the test phone can use the whole API over loopback, and Wi-Fi sharing is plain HTTP | Server and security | P0 | needs-review | 2026-09-24 | **Why P0:** with sharing on, anyone on the same Wi-Fi can read captured data without the PIN, by sniffing it. **Loopback.** `AccessControl` trusts every loopback caller with no auth (`KillcamServer.kt:144-159`). Any other app on the phone can therefore read traffic and tokens, run SQL, edit prefs, delete files, run actions and change mocks, as long as it sends `Host: 127.0.0.1` and `X-Killcam: 1`. README and API.md describe loopback trust only as "USB access". **Wi-Fi.** Sharing binds `0.0.0.0` over plain HTTP, so the PIN, the cookie and all captured data can be sniffed on the Wi-Fi. **Smaller issues:** tokens never expire until sharing is turned off; five wrong PINs lock `/api/auth` for everyone for 60 s, so anyone on the network can keep the tester locked out; the PIN is shown in the notification shade; the bridge is exposed to every frame in the WebView. **Security:** a developer decision is needed on how much to close; the design says "closed by default". |
